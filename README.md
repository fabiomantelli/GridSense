# Voltcase

**Drag in a COMTRADE record. Get a deterministic, second-by-second read on what the grid did — entirely in your browser.**

Voltcase parses IEEE C37.111 (COMTRADE) oscillography records, runs a deterministic analysis engine over every sample (RMS, phasors, symmetrical components, step-change detection, fault classification, breaker-trip correlation), and renders the result as interactive waveforms — without ever sending the file anywhere. The parser and analysis engine are Rust, compiled to WebAssembly, running in the same browser tab you dropped the file into.

**Live demo:** [grid-sense-nu.vercel.app](https://grid-sense-nu.vercel.app)

---

## Why deterministic first

Every fact Voltcase reports — *"Phase B to ground fault, current 4.7× pre-event baseline, breaker 52a opened 38 ms after onset"* — is computed by ordinary, auditable code: parsing, windowed RMS, phasor extraction, symmetrical-component math, threshold-based step detection, temporal correlation against digital channels. None of it is inferred by a language model, and none of it can be.

That's a deliberate choice. A protection engineer deciding whether a relay operated correctly cannot afford a tool that might plausibly invent a fact. So the pipeline is intentionally split:

```
COMTRADE file → Rust/WASM engine → structured facts → (optional) LLM explains it in plain language
```

The engine proves what happened, using nothing but the samples in the file. A language model, if and when one is wired in, only gets to *narrate* that already-proven result — never to compute it.

## What it does today

- **Parses COMTRADE** — ASCII and binary16 `.dat`, 1991/1999/2013 revisions, absolute (`dd/mm/yyyy,hh:mm:ss.ffffff`) and relative timestamps, analog and digital channels, real-world edge cases (`nrates=0`, per-phase-numbered channel naming, mixed vendor quirks).
- **Runs a deterministic analysis engine** — windowed RMS, phasor extraction, positive/negative/zero-sequence components, cycle-over-cycle step-change detection, fault classification (phase-to-ground, phase-to-phase, three-phase, unclassified), fault-current-vs-baseline ratio, and breaker-trip timing correlation against digital channels.
- **Compares records across substations** — pick two or more already-loaded records, align them on one real, absolute, synchronized time axis (not each record's own relative sample clock), and overlay any shared quantity (voltage, current, ...) with each record's own onset markers shown in its own color — directly answering *"which station's relay saw this first."*
- **Never uploads anything** — 100% client-side. The file is read, parsed, and analyzed in your browser's WebAssembly runtime; nothing is sent to a server, because there is no server.

## Running it

Nothing to install to try it — open the [live demo](https://grid-sense-nu.vercel.app) and drop in a `.cfg`/`.dat` pair.

### Build from source

**Prerequisites:** [Rust](https://rustup.rs/) with the `wasm32-unknown-unknown` target, [wasm-pack](https://rustwasm.github.io/wasm-pack/installer/), and [Node.js](https://nodejs.org/) 18+.

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack

cd app
npm install
npm run build     # builds the WASM core, then the Svelte app
npm run dev        # or: local dev server with hot reload
```

Other useful commands, run from `app/`:

```bash
npm run check       # svelte-check (TypeScript)
npm run test        # vitest
cargo test           # from the repo root — Rust unit/integration tests
```

## Architecture

```
crates/
  voltcase-core/   Rust — COMTRADE parser + deterministic analysis engine (no browser deps)
  voltcase-wasm/   Rust — thin wasm-bindgen adapter over voltcase-core
app/
  src/
    lib/            Parsing glue, file pairing, theming, WASM boundary
    components/     Svelte 5 UI — waveform charts (uPlot), facts panel, multi-record compare
    wasm-pkg/       Generated by `npm run build:wasm` — not committed
```

`voltcase-core` has no knowledge of WASM, the browser, or JavaScript — it's a plain Rust library, independently testable, and deliberately avoids heavyweight dependencies (no `chrono`, no `regex`) to keep the compiled WASM small. `voltcase-wasm` is a narrow adapter that exposes it to the frontend via `wasm-bindgen`. The Svelte app never computes an engineering result itself — it only renders what the Rust engine already decided.
